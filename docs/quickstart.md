# Quickstart

**About 10 minutes, with nothing to install.** At the end you'll have a first change of your own [merged](glossary.md#merge) into your project, made by Claude in a [cloud session](glossary.md#cloud-session) from the Claude desktop app or your browser. It's written for someone new to building: each step is one thing to do, and each word you may not know links to the [glossary](glossary.md). Developers can start from the README's [Getting started](../README.md#getting-started) instead.

1. **Have what you need:** a Claude plan that includes Claude Code (Pro, Max or Team, or an Enterprise seat that includes it; see [Claude's docs](https://code.claude.com/docs/en/web-quickstart)) and a [GitHub account](https://github.com/signup). A private [repository](glossary.md#repository) on GitHub's free plan is fine: the kit starts in [solo mode](glossary.md#solo-mode). Everything runs in the cloud, so there's nothing to install.

2. **Connect Claude to GitHub:** on a Team or Enterprise plan, your Claude organisation's Owner may first need to switch on the GitHub connector. Then go to [claude.ai/code](https://claude.ai/code), sign in, and follow its prompt to connect GitHub: approve on GitHub's page, and it sends you back. When it offers the Claude GitHub App, install it and choose **All repositories**, so it can reach the one you make next; if it doesn't offer it, install it from [the app's page](https://github.com/apps/claude/installations/new). **All repositories** lets Claude reach every repository you have. To keep it to one, install the app after step 3 instead, choosing **Only select repositories** and your new one. On Pro or Max this also makes your **Default** environment; on Team or Enterprise, click **Create & finish** on the form it shows. Claude's own steps: [Connect GitHub](https://code.claude.com/docs/en/web-quickstart#connect-github). GitHub's: [installing a GitHub App](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party).

3. **Make a repository of your own:** at [github.com/new](https://github.com/new), type a name (say `my-notes`), choose **Private**, switch on adding a README, and click **Create repository**. The README gives your project a first version for Claude's changes to go into. One you already have works too; if it's empty, add a README to it on GitHub first.

4. **Start a cloud session on it,** in the **Default** environment ([Claude's docs](https://code.claude.com/docs/en/claude-code-on-the-web)):
   - **Desktop app:** start a new Code session, choose **Cloud**, and pick the **Default** environment and your repository.
   - **Browser:** at claude.ai/code, pick your repository with the selector below the message box, and the **Default** environment.

5. **Send the set-up message,** copied exactly:

   > Set this repository up with the pairnexus workflow: clone https://github.com/medTech-group/pairnexus-workflow at its latest release's tag and follow `skills/setup-workflow/SKILL.md`.

   If Claude asks to add the kit's repository, or `mattpocock/skills`, to the session, allow it. Then it asks a few questions with choices to click, the recommended answer first: your [experience level](glossary.md#experience-level) (how much you know about building software), whether to copy the kit into your project (**Vendored**), your GitHub login, what data is sensitive here, and how to try changes. Type your own login; for the rest, the recommended answers are fine.

6. **Merge the set-up [pull request](glossary.md#pull-request-pr):** Claude opens one and gives you its link. Its description starts "Merge this and start working", and it only adds the kit. On GitHub, wait for its [checks](glossary.md#checks-ci) to turn green, then click **Merge pull request** and **Confirm merge**. If Claude then offers **[Protect `main`](glossary.md#protect-main)**, pick **Not now**: it's one of the next steps (step 10).

7. **Start a new session and ask for one small change:** start a new cloud session on your repository as in step 4, and say "Hi". The [guided start](glossary.md#guided-start) asks two questions: how much you know about building software (skipped when set-up already kept your answer), and "What are we working on?". For a brand-new project its first choice is **A brand-new project or a large effort**, which plans the whole project first and takes longer. Pick **Something new, or a change to what's there** instead, and describe something small and everyday, such as "Add a simple web page that says what this project is for" or "Add a page with our opening hours". When it asks "which way?", make it a quick [ticket](glossary.md#ticket), one small piece of work: pick **Quick ticket**, or pick **Other** and type "Quick ticket" if it isn't listed. Claude then writes your change up and builds it. After that, pick the recommended choice whenever it asks.

8. **Wait for its pull request to go green:** when the change is made, Claude opens a pull request and gives you its link. It starts with "In plain words": what changes for you, how to try it, and what could go wrong. Claude's [review panel](glossary.md#review-panel) has read the change already, and the checks now run by themselves: green when they pass, red when they fail. Wait until every one is green; if one turns red, ask Claude to fix it. A new project has no tests of its own yet, so Claude may say it found none to run: that's expected.

9. **Merge it** with GitHub's own button: on the pull request, click **Merge pull request**, then **Confirm merge**. Your change is now on [`main`](glossary.md#main), the finished version of your project. If it was wrong, ask Claude to [revert](glossary.md#revert) it: a new pull request takes it out again.

10. **Next steps, when you want them.** Your project works without them:
    - **[Protect `main`](glossary.md#protect-main)** (optional): GitHub itself then stops a mistake reaching `main`. Ask Claude to protect `main`. On your own computer, with `gh` signed in as the repository's admin, it does it for you. In a cloud session it gives you guided clicks. Once CI has run on `main`, it can require those checks too. A private repository needs a paid GitHub plan for it. See [the README's "Protect `main`"](../README.md#protect-main).
    - **[Check the set-up](glossary.md#check-the-set-up)** (optional): ask Claude to "check the set-up" (the `check-setup` skill) to see in one place what's set up and what's left, each with its fix. It changes nothing itself. See [the README's Step 6](../README.md#step-6-check-it).
    - **Set up [unattended runs](glossary.md#unattended-run)** (optional): Claude building your ready tickets while you're away. Ask Claude to set up unattended runs; see [the README's "Set up unattended runs"](../README.md#set-up-unattended-runs).
