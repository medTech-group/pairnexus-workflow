## Helpers

- `_read`: in `cli.py`, the text of a file a command was given, or standard input's for `-`. A file that can't be read raises `InputUnreadable` (an `OSError`, with the errno, reason and file name it had; an empty path, refused before reading, or standard input closed has no errno, and reads "no path was given" or "standard input (-) is closed"), one that isn't UTF-8 text, standard input's too, `InputNotText` (a `UnicodeDecodeError`), so a command that catches either words it itself; `main` refuses any other in one line, `` workflow: can't read `<path>`: <why> ``, never a traceback (#687). `_json` reads through it.
- `_issues_file`: in `cli.py`, a `--issues` or `--prs` file as the GitHub API lists it: a list of objects with a number (`doctor._number`), or `--paginate --slurp`'s pages of them, flattened with `_fetch_items`. Its text is read as JSON with `doctor._parse_json`. A file that isn't JSON, or isn't such a list, raises `InputUnreadable` with no errno, so `main` refuses it in one line (`_parse_json`'s reason, such as `` it isn't valid JSON (…) `` or `it is empty`, or `` it isn't a list of issues (it is …) ``). `workflow status` reads both its files with it (#757).
- `as_read`: in `status.py`, an issue or pull request as `workflow status` reads it: a copy with each field it reads that holds the wrong type left out (`state`, `state_reason`, `title`, `body`, `head` and its `ref`, `draft`; a sub-issue or dependency summary whose count isn't a whole number, left out whole), so the item reads as it would without that field, never a traceback; a `pull_request` of the wrong type, or null, still marks a pull request, read without its details. It leaves labels as they are: `issues.labels_of` reads past one of the wrong type (#772). `snapshot` reads every issue and pull request through it, from `--issues` and `--prs` files and `--fetch` alike (#770).
- `_paths`: in `evidence.py`, names paths in a message: the first five, then "and N more"; in a report, each a code span on one line (`_code`: in ASCII, quoted as git quotes it, `_git_quoted`, when it holds a control character, a byte outside ASCII, a double quote or a backslash, and fenced past its backticks).
- `_dirty_store`: in `evidence.py`, the emptied `<sha>-dirty` store, where a run keeps what didn't run on the commit itself (a dirty tree with `--allow-dirty`, or a tree that changed mid-run), apart from the commit's evidence and never reused.
- `tree_state`: in `evidence.py`, a look at the whole checkout's tree, from its top even when the project is a folder in it, outside the project's `.workflow/`: each tracked or staged path's index entries and `lstat`, and the untracked files that aren't ignored (a checked-out submodule's HEAD and its own tracked and untracked paths in its place), and the `lstat` of each folder that isn't ignored (one holding a tracked path, or none: an empty one, one holding only ignored files, and those beneath). `tree_changes` gives the paths that differ between two looks; read-only git commands change neither.
- `proc.run`: runs one of the kit's own short commands with no shell and no input, in a session of its own, and kills its whole process group whenever the caller stops waiting (a timeout, a Ctrl-C), holding a Ctrl-C that comes while it starts; a Ctrl-C still reaches the caller as `KeyboardInterrupt`. Doctor's `_run`, `workflow status`'s `git` call, the profile's `_git` and the evidence run's tree look (`_git_out` in `evidence.py`) use it.
- `proc.output`: what a command printed, as UTF-8 with other bytes replaced, when it exited 0; else None.
- `ascii_link`: in `research.py`, the link in ASCII: the host encoded by UTS 46 non-transitional rules, the userinfo, path, query and fragment percent-encoded as UTF-8. `fetch` sends a link outside ASCII without its userinfo, as a browser does; a link in ASCII as written. `fetch` and `link_problem` both use it, so a link that can be saved is one that can be fetched.
- `is_fingerprint_start`: in `research.py`, whether a file is a fingerprint file from its name and the start of its text (named `*.fingerprints`, or its first line a `url:` line); `research check` reads a topic's folder with it, and `workflow graph` leaves such files out.
- `sentences`: in `graph.py`, a text's sentences as spec #682's "What it gives back" ends them (an end mark with any closing quote, bracket, emphasis or backtick before a space or the line's end, except after "ans", "e.g" and "i.e"; a blank line; the end of a heading, a list item or a table row), with each line's pieces mapped to them, so a citation finds its sentence. Answer ids (#745) find theirs with it.
- `labels_of`: in `issues.py`, an issue's or pull request's labels, casefolded, as GitHub matches them: names, or objects with a text `name`; a label of any other type is read past, the others kept, and a `labels` field that isn't a list reads as none. `workflow status` reads labels only through it, `as_read` keeping no filter of its own; `ready`, `state` and `workflow graph` read them through it too (#772).
- `is_whole`: in `issues.py`, whether a value read from JSON or TOML is a whole number: an `int`, never a `bool`; a float such as `3.0`, a text such as `"3"` and None aren't. Every whole-number check in the kit calls it, adding its own range: `status._whole` (or missing), `state._int`, `doctor._number`, merge-check's numbers, the profile's and the charter's limits, and the readers of comment ids, findings' issue numbers and diff counts (#773).
- `escape_surrogates`: in `issues.py`, text with each lone surrogate (half a surrogate pair, which UTF-8 can't encode, so printing it ends in a traceback) written as JSON escapes it, `\ud800`; everything else is left as it is. `status.text` passes `workflow status`'s text through it, and `protection.printable` calls it (#774).
- `is_spec`: in `issues.py`, whether an issue is a spec: the `spec` label, or a "Spec:" title. `is_build_ticket`, `workflow status` and `workflow graph`'s `kind` use it.
- `replaces_lines`: in `graph.py`, the lines of a body's own `## Replaces` section, from its heading to the next, never from a fenced block or a `>` quote. `built_by` (#746) reads its ids from these lines.
- `holds_sensitive`: in `profile.py`, whether a text matches any of the profile's `[sensitive].patterns`. The guard (`_text_holds_sensitive`, which `_bash_holds_sensitive` calls) and `workflow graph`'s `_shown` use it, rather than each keeping its own `re.search` loop over the patterns (#756).
- `sensitive_match`: in `profile.py`, the first of the patterns found in a text, else None; the guard's two refusals that name the pattern use it, and `holds_sensitive` reads it (#756).
- `unnameable`: in `research.py`, why no key-source line could name a link (a space, a line break, a control character, `<` or `>`), else None. `ascii_link` and `link_problem` both refuse such a link with it.

## Rules

- `evidence.py`: a run keeps a shard's result as the commit's only after checking, once the shard has ended, the working tree and then that HEAD hasn't moved. A moved head stops the run with nothing kept for that shard, so a later run on the commit runs it again (#671). A tracked or staged path changed since the last look (`tree_state`, inside submodules too, the repair's window included), or with `--allow-dirty` an untracked file that appeared or a file created or removed in a folder that isn't ignored (an ignored file too, even one gone again), makes the run a dirty one: it goes on, keeps that shard and every later one under `<sha>-dirty`, and its report carries the dirty marker. Untracked files that appear without `--allow-dirty` are left be (#704). The base branch's worktree, fresh from git, isn't checked at all (#703).

- `profile.py`: every `git` call goes through `_git`, so through `proc.run`, and its timeout is a module-level seam (`GIT_TIMEOUT`, or `CODE_FILES_TIMEOUT` for the tracked files), never a literal at the call, so the Ctrl-C tests can raise it past their wait (#690).

- `graph.py`: the project graph reads the base branch only at `origin/<base>`, fetched first (`small.base_ref`), never the working tree, and writes nothing else; it reads the files that may cite an id through `git grep` at that ref (binary files left out by git), so only the files that may cite an id are read whole. It spends no model tokens. A run whose state can't be read never stops it: its line goes under the list, or to standard error with `--json`.

## Decisions

- Doctor's process-group kill (#684) moved into `proc.py` rather than being copied, so `workflow status` and the profile's `git` reads share it (#689).
- A host outside ASCII is encoded only where the standard library can be sure it encodes it as a browser does, and refused as can't fetch otherwise: the kit has no UTS 46 mapping table, and Python's own `idna` codec is IDNA 2003, which turns `faß.de` into `fass.de` (#532, [#560](https://github.com/medTech-group/pairnexus-workflow/pull/560)).
- `workflow graph cites` is its own module, `graph.py`, so the vendored copy's lock records when a project got it (spec #682, "The command's form"); its `--json` objects carry `built_by` and `changed_by` empty until #746 and #745 fill them, so the form is the spec's from the first ticket (#744).
